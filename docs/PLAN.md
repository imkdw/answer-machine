# answer-machine 계획서

누가 질문하면 답 대신 URL을 보낸다. URL을 열면 몇 초간 병맛 연출이 나오고, 마지막에 뿅 하고 답변이 뜬다.

## 1. 핵심 원칙

- 인프라 비용 0원. 서버 없음. 정적 파일만 배포한다.
- 답변 텍스트는 URL 자체에 인코딩한다. 저장소가 없으니 중복 처리, 스팸, 운영 부담이 없다.
- URL은 최대한 짧게.
- 접속할 때마다 연출이 다르다. 같은 URL을 열어도 매번 새 조합이 나온다.
- 우선순위는 "연출의 재미"가 항상 먼저다. 데이터, 통계, 인프라는 뒤로 미룬다.

## 2. 사용자 흐름

1. 작성자가 메인 화면에서 답변 텍스트를 입력하거나 프리셋 버튼을 누른다.
2. 브라우저가 텍스트를 인코딩해 `https://도메인/코드` URL을 만든다. 서버 요청 없음.
3. "복사" 버튼으로 URL을 복사해 질문자에게 보낸다.
4. 질문자가 열면 "답변이 도착했습니다. 탭해서 확인" 화면이 뜬다.
   브라우저 자동재생 정책 때문에 사용자 제스처가 있어야 소리가 나므로 이 탭은 필수다.
   탭을 기다리는 동안 씬 코드와 브금을 백그라운드로 미리 받는다.
5. 탭하면 랜덤 조합된 연출이 재생되고, 마지막에 답변이 화면 중앙에 나타난다.
6. 리빌 화면 아래에 "다시 보기"(새 조합으로 재생), "나도 답변 만들기", "URL 복사"를 둔다.

## 3. URL 인코딩

### 3.1 방식

- 한글 완성형 11172자, 자모 51자, ASCII 95자를 하나의 인덱스 공간에 두고 글자당 14비트로 채운다.
- 비트열을 6비트씩 잘라 base64url 알파벳(A-Z a-z 0-9 - _)으로 바꾼다.
- 그 외 문자(이모지, 한자 등)는 이스케이프 슬롯 하나를 두고 UTF-8 바이트를 뒤에 붙인다.
- 코드 앞 1자에 버전/모드 표시를 둔다. 나중에 인코딩을 바꿔도 예전 URL이 깨지지 않게.

측정 결과 (도메인 제외):

| 답변 | 글자 수 | UTF-8 base64 | 14비트 인코딩 |
|---|---|---|---|
| ㅇㅋ 가자 | 5 | 18자 | 12자 |
| 싫은데요 | 4 | 16자 | 10자 |
| 그건 좀 아닌 것 같은데 다시 생각해봐 | 21 | 68자 | 49자 |

### 3.2 사전 코드

- 자주 쓸 답변 50개 안팎을 클라이언트에 하드코딩하고 1~2자 코드로 매핑한다.
  예: `ㅇㅋ 가자` -> `/k3`, `싫은데요` -> `/n1`, `몰라` -> `/m0`
- 입력 텍스트를 정규화(앞뒤 공백 제거, 연속 공백 하나로)한 뒤 사전에 있으면 사전 코드, 없으면 14비트 인코딩을 쓴다.
- 사전은 한 번 배포하면 코드가 바뀌면 안 된다. 추가만 하고 삭제/변경은 하지 않는다.

### 3.3 부수 효과

- 커스텀 인코딩이라 눈으로는 못 읽는다. 스포일러 방지가 공짜다.
- 같은 문구는 항상 같은 URL이다.
- URL 길이의 절반은 도메인이다. 짧은 도메인을 사면 효과가 가장 크다. 유일하게 돈이 들 수 있는 항목이라 선택사항이다.

### 3.4 제한

- 최대 200자. 넘으면 입력 화면에서 막는다.
- 빈 문자열 거부.

## 4. 연출 시스템

### 4.1 씬 플레이어

연출 하나를 통짜로 만들지 않는다. 각 연출은 독립된 씬이고, 플레이어는 씬 배열을 순서대로 재생한 뒤 리빌 씬으로 끝낸다.

```ts
interface Scene {
  id: string
  tags: SceneTag[]          // opener | buildup | fakeout | chaos | reveal
  duration: number          // ms. 씬이 직접 onDone을 부를 수도 있음
  weight: number            // 뽑힐 확률 가중치
  rarity: 'common' | 'rare' | 'legendary'
  component: React.ComponentType<SceneProps>
}

interface SceneProps {
  answer: string
  onDone: () => void
  audio: AudioBus           // 효과음 트리거, 브금 제어
  extendTime: (ms: number) => void   // 스킵 버튼이 시간 늘릴 때 사용
}
```

씬을 추가하려면 컴포넌트 하나 만들고 레지스트리에 등록하면 끝나야 한다.

### 4.2 랜덤 조합 (매 접속마다 다르게)

- 시드 없이 매번 `Math.random()`으로 뽑는다. 같은 URL도 매번 다르다.
- 조합 규칙:
  - opener 1개
  - buildup / fakeout / chaos 중 2~3개, 같은 씬 중복 없음, 같은 태그 연속 지양
  - reveal 1개
- 총 길이 예산 8~15초. 뽑은 씬들의 duration 합이 예산 안에 들도록 채운다.
- 직전 재생 조합을 sessionStorage에 두고 "다시 보기"에서는 다른 조합이 나오게 한다.
- 희귀도:
  - common: 대부분
  - rare: 10% 정도 확률로 섞임
  - legendary: 1% 정도. 예: 연출 없이 바로 답변이 뜨고 "오늘은 봐줌" 한 줄. 또는 답변 대신 "답변이 도망갔습니다" 후 재시작

### 4.3 변주 레이어

씬 조합 위에 독립적인 랜덤 레이어를 얹어 조합 수를 곱으로 늘린다.

- 테마: 색상 팔레트, 폰트(궁서체, 90년대 홈페이지, 윈도우 XP, 네온, 흑백 무성영화 등), 배경
- 브금: 3~5곡 중 랜덤
- 효과음 세트: 드럼롤 종류, 뿅 소리 종류
- 텍스트 변주: 로딩 문구, 스킵 반응 대사, 시스템 메시지는 풀에서 랜덤

씬 10개, 테마 5개, 브금 4개만 있어도 체감상 매번 다르다.

### 4.4 씬 아이디어 풀

opener
- 두구두구: 드럼롤 + 화면 진동 + 점점 커지는 "두구두구두구"
- 뉴스 속보: 빨간 자막 "긴급 속보" + 뉴스 시그널
- 카운트다운: 3, 2, 1 그리고 "잠깐" 하고 10부터 다시
- 전원 켜짐: 옛날 CRT 켜지는 효과 + 삐 소리

buildup
- 가짜 로딩바: 99%에서 멈춰 3초 버팀, 헛소리 상태 문구가 계속 바뀜 ("답변 압축 해제 중", "감정 이입 중", "눈치 보는 중")
- 답변 생성 AI: 타이핑 효과로 엉뚱한 답을 쓰다가 전부 지우고 "아 아니다"
- 로또 추첨기: 공이 돌다가 글자가 하나씩 뽑힘
- 뽑기 기계: 캡슐이 떨어지고 열리는 척
- 심사위원 채점: 심사위원 3명이 점수판 드는 척하다가 전원 "?"

fakeout
- 가짜 광고: "5초 후 건너뛰기" 카운트가 4에서 다시 5로 올라감
- 가짜 블루스크린 / "연결이 끊겼습니다" 1.5초
- 가짜 캡차: "당신이 사람임을 증명하세요" 체크박스, 누르면 "실패"
- 가짜 팝업: "답변을 보려면 로그인" 하고 닫히면서 "농담"
- 가짜 새로고침: 화면이 흰색으로 깜빡이고 탭 시작 화면으로 돌아간 척

chaos
- 화면 회전/뒤집기: 페이지 전체가 뒤집힌 채 "잠시만요"
- 이모지 폭풍: 화면 가득 이모지가 날아다님
- 도망가는 버튼: "답변 보기" 버튼이 손가락을 피함, 3번 실패하면 자동 진행
- 텍스트 붕괴: 글자들이 중력에 떨어져 바닥에 쌓임
- 줌 지옥: 화면이 계속 확대되다가 픽셀 하나에서 멈춤

reveal
- 뿅: 화면 번쩍 + 콘페티 + 스프링 팝업 (기본)
- 폭발: 화면이 터지면서 잔해 사이로 답변
- 두루마리: 옛날 조서 펼치기, 궁서체
- 판정: 격투게임 K.O. 연출 후 답변
- 속삭임: 화면이 어두워지고 아주 작게 답변, 탭하면 커짐
- 로또 발표: 당첨번호 발표 톤으로 글자 하나씩

### 4.5 페이크 스킵 버튼

"건너뛰기" 버튼을 항상 보이게 두고, 누른 횟수에 따라 반응이 바뀐다. 반응 대사는 풀에서 랜덤.

1. 1회: 버튼 텍스트가 "응 안되쥬~"로 바뀌며 흔들림 + 삐 소리
2. 2회: "ㅋㅋ 또 눌렀네" 토스트 + 연출 3초 추가
3. 3회: 버튼이 손가락을 피해 도망감
4. 4회 이후: 가짜 시스템 팝업 "스킵 요청이 반려되었습니다 (사유: 그냥)", 버튼이 화면 밖으로 날아감
5. 7회 이상: "축하합니다. 인내심 테스트 통과" 후 씬 하나 추가

리빌 화면에 "스킵 시도 N회"를 표시한다.

### 4.6 사운드

- 효과음(드럼롤, 뿅, 삐, 찌지직, 팡)은 Web Audio API로 합성한다. 파일 없고 저작권 문제 없음.
- 브금은 무료 라이선스(Pixabay 등) 3~5곡. 탭 대기 중에 프리로드.
- 음소거 토글은 항상 보이게. 상태는 localStorage.
- 오디오 컨텍스트는 첫 탭 제스처에서 생성한다.

### 4.7 꼴받음 추가 기획

리빌 직전/직후에 끼워 넣을 수 있는 장치들. 전부 씬 또는 리빌 변형으로 구현 가능하다.

리빌 직전 (마지막 한 방)
- 3단 확인: "정말 보시겠습니까?" -> "확실합니까?" -> "진짜요?" 순서로 물어본다. "아니오"를 누르면 "그럴 줄 알았음" 하고 처음부터.
- 가짜 답변 먼저: 그럴싸한 다른 답("싫어")을 먼저 보여주고 2초 뒤 "농담 ㅋㅋ 진짜 답은" 하고 진짜 답. 진짜 답이 긍정이면 가짜는 부정으로, 반대도 마찬가지.
- 마지막 글자 지연: 답변을 한 글자씩 띄우다가 마지막 글자 직전에 "로딩 중" 3초.
- 초성 퀴즈: "ㅇㅋ ㄱㅈ" 초성만 보여주고 "맞춰봐" 입력창. 정답을 넣어도 "그래도 안 보여줌".
- 입력 중 페이크: 카톡처럼 "상대방이 입력 중..." 점 세 개가 10초 동안 깜빡임.
- 약관 동의: "답변 열람 이용약관"을 끝까지 스크롤해야 동의 버튼이 활성화된다. 약관 내용은 전부 헛소리.
- 절대 누르지 마시오: 빨간 버튼 하나만 있고 안 누르면 영원히 대기. 누르면 "그럴 줄 알았다" 하고 진행.
- 가로/세로 트롤: "가로 모드에서만 볼 수 있음" 하고 돌리면 "세로 모드에서만 볼 수 있음". 두 번째엔 진행.
- 폰 흔들기: 모바일 가속도계로 "폰을 흔들어서 답변을 털어내세요". 데스크톱은 마우스를 마구 흔들기.

리빌 직후
- 재모자이크: 답변이 뜨고 3초 지나면 다시 모자이크. "다시 보려면 처음부터" 버튼. (rare)
- 잘못 보냄: 답변이 뜨고 2초 뒤 "앗 잘못 보냄" 하고 사라진 다음 연출 하나 더 붙고 같은 답이 다시 나온다. (rare)
- 도움 됐나요: "이 답변이 도움이 되었나요? 👍👎". 반응은 4.8 청개구리 버튼 참고.
- 페이크 통계: "이 답변을 본 사람 4,832명 (당신 제외)", "평균 대기 시간 12.4초. 당신은 상위 3% 인내심".
- 마지막 한 줄: "참고로 질문한 사람은 이미 답을 알고 있었음".
- 스킵 시도 횟수 공개: "스킵 시도 7회. 다 봤음."

작성자 쪽 옵션 (URL 코드 1자에 담는다)
- 꼴받음 강도 1~3: 연출 길이와 페이크 씬 개수가 달라진다. 3이면 3단 확인과 약관 동의가 확정 포함.
- 공개 시각 예약: "18:00 이후 열람 가능". 그 전에 열면 카운트다운만 보여준다. 시각은 코드에 추가 인코딩. (Phase 3 이후 검토)

넣지 않을 것
- 볼륨 트롤(작은 소리로 유도한 뒤 큰 소리). 청각에 해로울 수 있어 제외.
- 실제 권한 요청(마이크, 위치 등). 브라우저 권한 팝업은 재미가 아니라 불신을 준다. 페이크 UI로만 한다.
- 뒤로가기 막기. 브라우저 히스토리 조작은 안 한다.

### 4.8 청개구리 버튼

원칙: 받는 사람 화면의 버튼은 사용자가 누른 것과 다르게 반응한다. 단, 아래 세 가지는 지킨다.
- 결국은 진행된다. 어떤 버튼을 눌러도 답변까지 도달한다. 영구히 막히는 경로는 없다.
- 작성자 화면(입력, URL 생성)은 정상 동작한다. 여기서 장난치면 URL을 못 만든다. 트롤은 받는 사람 화면에서만.
- 진짜 기능(음소거, 복사)은 결국 동작한다. 멘트와 딜레이로만 놀린다.
- 같은 버튼을 두 번 누르면 다른 반응이 나온다. 반응 멘트는 풀에서 랜덤.

피드백/평가류
- 도움이 되었나요? 👍 -> "도움이 안 됐다고 하셨습니다. 수고용" / 👎 -> "도움이 됐다니 다행이네요"
- 별점: 5점 주면 "1점 접수되었습니다", 1점 주면 "5점 감사합니다"
- 신고하기 -> "신고가 접수되었습니다. 신고 대상: 당신"
- 좋아요 -> 카운트가 1 줄어듦

확인/선택류
- 정말 보시겠습니까? 예 -> "안 보신다고 하셨군요" 하고 연출 하나 추가 / 아니오 -> "그럼 보여드림" 하고 바로 진행
- 확인/취소: 확인이 취소 동작, 취소가 확인 동작. 호버하면 두 라벨이 서로 자리를 바꾼다
- 절대 누르지 마시오 -> 누르면 "누를 줄 알았음", 10초 안 누르면 "인내심 테스트 통과. 근데 어차피 진행"
- 가짜 캡차 체크박스: 체크하면 바로 해제되며 "로봇 확정"

속도/제어류
- 건너뛰기 -> 연출 추가 (4.5)
- 빨리 보기 -> 슬로우모션으로 전환, 두 번째 누르면 "더 빨리?" 하고 더 느려짐
- 답변 공개 속도 슬라이더 -> 오른쪽(빠름)으로 갈수록 느려짐
- 일시정지 -> 연출은 멈추는데 타이머는 계속 감 (남은 시간이 안 줄어듦)
- 앱 안의 뒤로가기 화살표 -> 다음 씬으로 감

닫기/이탈류
- 팝업 X 버튼 -> 팝업이 하나 더 열림. 3번째에 닫힘
- 닫기 버튼이 커서 근처에서 슬쩍 위치를 바꿈 (1~2회만)
- 새로고침 안내 "안 되면 새로고침 해보세요" -> 새로고침해도 sessionStorage로 같은 지점에서 재개. "도망 못 감"

기능 버튼 (동작은 함)
- 음소거 -> 첫 클릭에 "음소거 요청 접수. 검토 중..." 1초 뒤 실제 음소거. 두 번째부터는 즉시
- URL 복사 -> 실제로 복사되지만 토스트는 "복사 실패 ㅋㅋ", 1초 뒤 "농담. 복사됨"
- 다시 보기 -> "또 보게요?" 확인창, 어느 쪽을 눌러도 재생. 연출은 한 개 더 김
- 나도 만들기 -> "재능 없으실 것 같은데" 토스트 후 정상 이동
- 공유 -> "공유할 친구가 있으신가요?" 하고 정상 동작

라벨 트롤
- "답변 보기" 버튼에 호버/터치 시작하면 라벨이 "답변 안 보기"로 바뀜. 눌러도 진행은 됨
- 버튼 라벨이 누를 때마다 존댓말 -> 반말 -> 사투리로 바뀜
- 로딩 중 버튼 라벨: "잠시만요" -> "조금만요" -> "거의 다 됐어요" -> "거짓말이에요"

구현 메모
- 버튼 반응은 `TrollButton` 컴포넌트 하나로 통일한다. props로 `onPress`(실제 동작), `reactions[]`(누른 횟수별 멘트/동작)을 받는다.
- 반응 멘트는 `copy/` 폴더에 풀로 모아두고 랜덤으로 뽑는다. 씬과 분리해서 대사만 늘리기 쉽게.

## 5. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + React + TypeScript | 정적 SPA, 가볍고 빠름 |
| 라우팅 | react-router (또는 직접 파싱) | `/`, `/:code` 두 개뿐 |
| 애니메이션 | Framer Motion + CSS keyframes | 씬 전환, 스프링 리빌 |
| 스타일 | Tailwind | 병맛 스타일 빠르게 |
| 사운드 | Web Audio API 직접, 브금은 Howler.js | 합성은 직접, 파일 재생은 Howler |
| 테스트 | Vitest | codec 왕복 테스트 필수 |
| 배포 | Cloudflare Pages | 무료, 대역폭 무제한, 엣지 정적 서빙 |

### 5.1 성능

- 첫 화면(탭 대기)은 최소 번들로 즉시 그린다.
- 씬 모듈은 동적 import로 코드 스플리팅. 탭 대기 중에 프리페치.
- 브금은 탭 대기 중 프리로드, 첫 씬은 합성 효과음만 써서 브금 로딩을 기다리지 않는다.
- 폰트는 시스템 폰트 우선. 특수 폰트(궁서체 등)는 해당 테마가 뽑힐 때만 로드.

### 5.2 Cloudflare Pages

- GitHub 연결, push마다 자동 배포.
- SPA 라우팅: `public/_redirects`에 `/* /index.html 200`.
- OG 메타는 `index.html`에 고정으로 박는다. `_redirects` 200 rewrite 덕분에 `/코드` 어떤 URL이든 크롤러가 같은 HTML을 받아 미리보기가 뜬다.
- 상세는 5.3 참고.

### 5.3 오픈그래프 (링크 미리보기)

원칙: 답변 내용은 절대 미리보기에 안 나온다. "눌러야 볼 수 있다"만 꼴받게 어필한다.

메타 텍스트 (카톡, 디스코드, 슬랙 공통)
- og:title: "눌러서 대답 확인하기"
- og:description: "여기선 안 보여줌. 눌러야 함."
- 후보 문구 풀: "궁금하지? ㅋㅋ", "답은 이 안에 있다", "3초면 됨 (거짓말)", "스포 없음. 직접 봐라"

썸네일 이미지 (1200x630, `public/og.png`)
- 일단 보류. 구해서 넣는다.
- 방향만 메모: 정중앙에 "눌러서 확인" 큰 글씨, 모자이크된 말풍선, 손가락이 버튼 가리키는 구도, 카톡 채팅창에서 튀는 배색

동작
- OG 메타는 `index.html`에 고정. `_redirects` 200 rewrite 덕분에 `/코드` 어떤 URL이든 크롤러가 같은 HTML을 받는다.
- 나중에 확장 (선택): Cloudflare Pages Functions(무료 티어 일 10만 요청)로 크롤러 User-Agent만 감지해 문구/이미지를 랜덤 회전. 일반 사용자는 정적 파일 그대로 받는다.

## 7. 개발 편의

- `?scene=fakeAd` 쿼리로 특정 씬만 바로 재생. 씬 개발할 때 필수.
